# VR-тренажёр «Коксовая батарея»

VR-тренажёр для рабочих коксового цеха. Сейчас в нём один сценарий — **осмотр газового тоннеля** — в двух режимах:
**обучение** (с подсказками и озвучкой) и **экзамен** (без подсказок, со временем, журналом и итоговым результатом).

- Движок: **Unity 6000.3.10f1** (Unity 6.3 LTS), URP
- VR: XR Interaction Toolkit 3.3.2 + XR Interaction Simulator (для проверки без шлема)
- Платформа запуска: **Windows + SteamVR** (сборка `.exe`)

## Как запустить проект

1. Клонировать репозиторий (GitHub Desktop → Clone). ZIP не подходит: теряется история.
2. Установить через Unity Hub редактор **6000.3.10f1**, версия указана в `ProjectSettings/ProjectVersion.txt`.
3. Unity Hub → Add → папка проекта. Первый импорт долгий: папка `Library` в гите не хранится, Unity соберёт её сам.
4. Открыть `Assets/Scenes/MenuScene` и нажать Play. Меню выбора режима → «Обучение» или «Экзамен».

Управление в симуляторе (без шлема) показано в окошках внизу экрана Game.

## Структура

| Путь | Что там |

## Режимы

Режим хранится в статической переменной `ExamMode.Active` (`UI/Scripts/ExamMode.cs`). Она переживает загрузку сцены.
Кнопки в MenuScene вызывают `ExamModeSetter.SetLearn()` / `SetExam()` (объект `ExamModeSetter` в MenuScene).
В FirstScene `ExamController` в режиме обучения сразу выключается и ничего не делает.

**Обучение:** синие круги-указатели, окна шагов, ромбики и карточки на деталях, голосовое приветствие.

**Экзамен** (`ExamController`):
- подсказки, ромбики, синие круги и голос выключены;
- время считается с входа в газовый тоннель;
- деталь осматривается, если держать на ней луч 2 секунды;
- конденсатоотводчик осматривается лучом на точку `ExamCondensateTarget` (пустой объект в яме), 3 секунды;
- выбор СИЗ в раздевалке не показывает вердикт: результат скрыт до итогового окна;
- газоанализатор пищит только если он выбран в СИЗ;
- журнал (иконка справа вверху) принимает запись только после осмотра всего нужного, иначе пишет «Не осмотрено (…)» и не засчитывает;
- выход — ручка двери: окно из 3 карточек (два перехода в другие помещения и «Завершить экзамен»), затем итоговое окно с временем, «N из M» и списком заданий.

## Сценарий как данные

Задания и привязка к деталям описаны в `ScenarioDefinition` (`UI/Scripts/ScenarioDefinition.cs`), а не в коде контроллера:
- список заданий: название, короткое имя для журнала, тип (`TaskKind`: `Ppe`, `Inspect`, `Journal`, `Drain`, `RayPoint`), обязательность для записи в журнале;
- правила `MatchRule`: к какому заданию относится точка осмотра (по полям `group` и `title` компонента `InspectPoint`). Задания проверяются по порядку, побеждает первое подходящее;
- число заданий для зачёта (`passMinTasks`, 0 = все) и тексты записи в журнале.

Откуда берётся сценарий: поле `scenario` у `ExamController` → ассет `Assets/Resources/Scenarios/TunnelInspection` → встроенный `ScenarioDefinition.TunnelInspection()`.
Чтобы править задания в Inspector, нужно создать ассет: меню **Koks → Scenario → Создать ассет «Осмотр тоннелей»**.

Итоговое окно собирается меню 20 под фиксированное число строк. Если у сценария другое число заданий, окно нужно собрать заново (меню 20).

## Результаты прохождений

В конце экзамена формируется `SessionRecord` (`UI/Scripts/SessionRecord.cs`): сценарий, режим, сотрудник, дата, время, список заданий, ошибки, зачёт.
`ResultStore` пишет его в **Документы/KoksTrainer/**:
- `results.jsonl` — полная запись, по строке на прохождение;
- `results.csv` — краткая таблица для Excel (разделитель `;`, кодировка UTF-8).

Ошибки фиксируются кодами: `ppe_not_checked`, `ppe_wrong`, `no_gas_analyzer`, `journal_without_inspection`. Новые ошибки добавляются через `AddError(code, text)` в контроллере.
Куда сохранять, задаёт `ResultStore.Sink` (интерфейс `IResultSink`): сейчас файлы, позже можно подставить отправку на сервер или в LMS без правки сценариев.
Выбор сотрудника пока не сделан: поле `SessionInfo.Employee` пустое.

## Как работать с проектом

1. Забрать изменения (Pull в GitHub Desktop), в Unity принять Reload.
2. Если менялся интерфейс: открыть нужную сцену и запустить меню `Koks → Build UI → N`. Для окон экзамена в FirstScene это **меню 20**, для окна выбора режима в MenuScene — **меню 21**.
3. Сделать Commit сцен (`.unity`), потом Push. Скрипты и сцены коммитятся вместе, иначе у коллеги сцена будет ссылаться на отсутствующие компоненты.

## Тонкости и грабли

- **Имя файла = имя класса.** В Unity 6.3 `MonoBehaviour` должен лежать в файле с таким же именем. Иначе в сцене компонент превращается в «missing», а вызовы из кнопок (UnityEvent) молча перестают работать. Так ломались `ExamModeSetter` и `UIHover`.
- **Не править старые скрипты в кодировке cp1251** (`WelcomeAudioPlayer`, `ClothingItem`, `FadeTeleport`, `ScenLoader` и подобные): русские комментарии портятся. Новые файлы пишем в UTF-8. `DressingChecker.cs` уже в UTF-8 с BOM.
- **Тексты из Inspector важнее текстов в коде.** Строки, сохранённые в сцене, перекрывают значения по умолчанию из C#. Поменяли текст в скрипте, а в игре старый — надо перезапустить сборку окон (меню 20/21).
- **Лучи и окна.** Окна в мире ловят луч через `TrackedDeviceGraphicRaycaster`. Правила: у кнопки должен быть `targetGraphic` с включённым `raycastTarget`; соседние картинки поверх кнопки перехватывают луч (поэтому у остальных графиков `raycastTarget` выключают); если выключить `raycastTarget` у всех графиков кнопки, на неё нельзя навести.
- **Окна перед преградами.** Если окно оказывается за дверью или стеной, луч упирается в коллайдер и кнопки не нажимаются. `WindowFit.Free` ставит окно перед преградой и пропорционально уменьшает.
- **Окна не следуют за головой.** Окно ставится один раз перед игроком и только поворачивается к нему (`FaceCamera`). Окно, которое плывёт за головой, нельзя прицельно навести.
- **`WindowRayGate`** отключает интерактивные объекты сцены, пока открыто окно (`StepWindow.AnyOpen`), чтобы луч не срабатывал на детали за окном.
- **Окно выхода** делается из копии старого `CanvasExit`: переходы берутся из окна того помещения, где игрок нажал ручку.
- **Огромные коллайдеры.** У точки осмотра конденсатоотводчика коллайдер на весь тоннель, поэтому она не считается по лучу в коллайдер: осмотр идёт по точке `ExamCondensateTarget` (и в обучении ромбик ставится в эту точку).
- **Повторяющиеся детали** (например, «Опорный ролик» в двух группах): достаточно осмотреть одну.

## Как добавить новый сценарий

1. Сделать сцену с точками осмотра (`InspectPoint`): заполнить `group` и `title`.
2. Описать задания в `ScenarioDefinition` (новый ассет: Create → Koks → Сценарий), привязать правила к `group`/`title`.
3. Если нужны новые типы заданий или проверки, добавить `TaskKind` и обработку в `ExamController`. Пока контроллер заточен под сцену тоннеля (кран сточной линии, журнал, конденсатоотводчик) — это следующий этап обобщения.
4. Проверить в Console строки `[Exam]`: при старте выводится, какие детали вошли в каждое задание.

## Известные ограничения

- Выбора сотрудника нет, результаты пишутся с пустым полем «сотрудник».
- Запись результатов есть только у экзамена; обучение результатов не пишет.
- Файлы результатов не защищены от правки: если они влияют на допуск, нужна подпись или отправка на сервер.
